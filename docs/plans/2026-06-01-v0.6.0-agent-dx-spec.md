# v0.6.0 Spec — agent DX: a cheap, easy pipe

**Date:** 2026-06-01
**Status:** Draft for implementation
**Parent:** `docs/plans/2026-06-01-agent-gateway-roadmap.md`
**Scope:** v0.6.0 = the three agent-DX items. The roadmap's fourth v0.6.0 item
(honest per-provider quota) is **deferred** to a later release — it is a distinct
"cost trust" theme that needs live per-provider free-tier metering research, not
agent ergonomics.

---

## North star (binding)

Nólë is a local, free-first/BYOK web search and page extraction router for AI
agents and coding CLI tools. It has no LLM, makes no quality judgment, and
performs **no synthesis**. v0.6.0 makes the routing layer cheaper and easier for
the agent to consume: fewer wasted tokens, fewer round-trips, and the richest
output (multi-source evidence) finally reachable — while Nólë keeps handing over
evidence, never composing the answer.

## What v0.6.0 fixes (dogfood-validated in the v0.5.0 cycle)

- **Every MCP search/extract response inlines the full `route_trace` debug blob**
  (MarshalIndent of per-attempt provider/status/reason/cost/cache/latency). The
  CLI has `--insight off|compact|verbose`; MCP/REST have no equivalent, so a
  debugging aid is forced into every agent turn's context (~2.4 KB for 3 results
  measured live).
- **The dominant workflow — search then read the top hit — is two MCP
  round-trips** (second routing pass, second quota gate, second context dump).
  No combined primitive.
- **`research` (multi-step search→extract→dedup) is CLI-only** and ships a
  `synthesizeSummary` that string-concatenates page extracts *including nav
  cruft* — a degraded "answer" that invites the exact Perplexity comparison the
  positioning rejects, while the genuinely useful part (clean multi-source
  evidence) is unreachable by the agents Nólë serves.

## Design decisions

### D1 — `route_trace` opt-in on MCP and REST
- **MCP:** add an `include_trace` boolean arg (default `false`) to the `search`
  and `extract` tools. When false, omit `RouteTrace` from the marshaled response
  (keep the compact `routing_insight` — it is small and the on-mission
  "explain what happened" surface). When true, include the full trace.
- **REST:** add an `include_trace` boolean field to the `/api/search` and
  `/api/extract` request bodies (default false), same effect.
- Implementation: strip `resp.RouteTrace = nil` before marshaling when not
  requested. `routing_insight` stays. CLI behavior is unchanged (`--insight`
  already governs it there).
- **Why:** the trace is a debugging aid; defaulting it off respects the agent's
  context budget, mirroring CLI `--insight compact`.

### D2 — `search_and_extract` primitive
- New `core.Service` method `SearchAndExtract(ctx, req)` that runs `Search`,
  then `Extract` on the top N result URLs (N from `extract_top`, default 1,
  clamped to a small max e.g. 3), returning a combined response
  (`SearchAndExtractResponse`: the search results + an `extracts` slice).
- **MCP tool** `search_and_extract` (args: `query`, optional `task`,
  `limit`, `extract_top`) and **REST** `POST /api/search_and_extract`.
- Honest cost: it debits one search + N extracts and the response/insight makes
  that visible (each extract carries its own provider). SSRF preflight still runs
  per extracted URL (via `Service.Extract`). Extract failures on a URL are
  non-fatal (skip + note), so a single bad URL never sinks the call.
- **Why:** collapses the N+1 round-trip for the most common agent task; one
  routing context, one response.

### D3 — Expose `research` over MCP/REST and DROP `synthesizeSummary`
- **Move the research pipeline into `core`**: `core.Service.Research(ctx,
  question, maxSteps) (ResearchReport, error)`, with `ResearchReport` /
  `ResearchSource` / `ResearchExtract` and `classifiedResearchTasks` moved from
  `internal/cli/research.go` to `internal/core`. (mcpserver/http import `core`,
  not `cli`, so the logic must live in core to be shared.)
- **DROP `synthesizeSummary` and the `Summary` field.** `ResearchReport` returns
  `{question, sources, extracts, providers_used, steps}` — structured evidence,
  no composed answer. The agent synthesizes.
- **MCP tool** `research` (args: `question`, optional `max_steps`) and **REST**
  `POST /api/research`.
- **CLI** `nole research` becomes a thin wrapper over `svc.Research` and prints
  the sources + extracts (no summary). Cancellation handling is preserved.
- **Why:** unlocks Nólë's richest output to its actual audience while finally
  honoring "evidence, not answers" — resolves the positioning contradiction.

## Non-goals (v0.6.0)
- Honest per-provider quota model (deferred — distinct theme, needs live
  metering research).
- No LLM / synthesis / answer composition (dropping the summary, not improving
  it).
- No change to routing/classification (that was v0.5.0).
- No new providers, no matrix reorder.

## Files in scope (anchors; grounding produces exact briefs)
- `internal/core/types.go` — `SearchAndExtractResponse`; move `ResearchReport`/
  `ResearchSource`/`ResearchExtract` here (drop `Summary`).
- `internal/core/service.go` — `SearchAndExtract`, `Research` methods.
- `internal/core/research.go` (new) — pipeline + `classifiedResearchTasks`
  moved from cli, minus `synthesizeSummary`.
- `internal/cli/research.go` — thin wrapper over `svc.Research`; print
  sources/extracts; drop `synthesizeSummary` + `printResearchReport` summary line.
- `internal/mcpserver/tools.go` — `include_trace` on search/extract;
  `search_and_extract` + `research` tools.
- `internal/cli/http.go` — `include_trace` on /api/search,/api/extract;
  `/api/search_and_extract` + `/api/research` routes.
- Tests across (new + updated; research_test loses summary assertions).

## Success criteria
- An MCP `search` with no `include_trace` returns results + `routing_insight`
  and **no** `route_trace`; with `include_trace:true` the trace is present.
- `search_and_extract` returns search results + extracted content for the top
  result in a single call; a bad top URL is skipped, not fatal.
- `research` is callable over MCP and REST, returns sources+extracts+providers,
  and carries **no** `summary`/composed answer anywhere (CLI included).
- Full gate green: `gofmt`, `go vet`, `go test -race ./...`, `audit.sh --ci`,
  `secret-scan.sh`. No breaking change to the `search`/`extract` response beyond
  trace becoming opt-in (additive args; trace omission is the intended change and
  is documented).
