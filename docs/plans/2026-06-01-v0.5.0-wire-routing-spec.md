# v0.5.0 Spec — Make the router actually route

**Date:** 2026-06-01
**Status:** Draft for implementation
**Parent:** `docs/plans/2026-06-01-agent-gateway-roadmap.md`
**Scope:** v0.5.0 only (the core). v0.6.0/v0.7.0 are separate spec→plan cycles.

---

## North star (binding constraint)

Nólë is the internet **gateway** for frontier agents — it is **not an AI**, never
judges result quality, never synthesizes answers. The agent thinks; Nólë routes
to the best provider for a task and returns clean raw material plus whatever
signals the provider already handed it. Every change below is judged by: *does
this make the agent's web search measurably better/fresher/more citable?* — not
*is Nólë smarter?*

## What v0.5.0 fixes (the one real bug, validated by dogfood 2026-06-01)

Firsthand, on real providers:
- `classify "what concerts are happening in Istanbul this week"` → `general,
  score:0`. The curated task→provider matrix never even gets the right task.
- `search` with no task and `search --task news` returned **byte-identical**
  top results, and the result object is `{title,url,snippet,provider}` — **no
  date, no relevance score**. So "news" delivers zero freshness/citability
  benefit, and Tavily's relevance `Score` (which the adapter receives) is
  dropped on the floor.
- The MCP `search` tool's `task` is **free-text (no enum)** and there is no
  "auto-detected if omitted" affordance; `Service.Search` takes `req.Task`
  verbatim and defaults empty → `TaskGeneral`, so the planner never fires.

v0.5.0 makes the **good static task→provider mapping actually fire on every
surface**, and makes task-fit shape the **request and the output**, not just the
provider order — without adding any intelligence to Nólë.

## Design decisions (settled)

### D1 — Task routing contract: agent specifies, Nólë classifies as fallback
- **MCP `search` `task` becomes a constrained enum** (`general | news | docs |
  academic | code | community | factcheck | people | pricing | research`) with a
  one-line description per value, and the param doc states: *"Optional. If
  omitted, Nólë auto-detects the task from the query."* The agent is the smart
  one and usually knows the task; the enum makes that explicit and typo-proof.
- **`Service.Search` auto-classifies when `req.Task` is empty**: call
  `ClassifyQuery(query, …).PrimaryTask` and use it. An explicit task always
  wins (override). This single change lights up CLI **and** MCP **and** REST
  (all funnel through `Service.Search`).
- **Surface how the task was chosen.** Add `task_source` to the search response
  envelope: `"supplied"` (caller gave it), `"detected"` (planner inferred), or
  `"default"` (planner found nothing → general). Goes in `route_trace` /
  `routing_insight` too, so the agent can see what happened (transparency, not
  intelligence).
- **Leniency:** an unknown/invalid task string from a caller must NOT error —
  treat it as omitted (classify/fallback to general). Backward-compatible:
  existing callers passing valid tasks are unaffected.

### D2 — Pass provider signals through (for the AGENT to judge)
- Add optional fields to `core.SearchResult` (all `omitempty`, JSON-backward-compatible):
  - `Score *float64` — provider-native relevance (e.g. Tavily `score`). Nil when
    the provider gives none. **Nólë does NOT compute its own score.**
  - `PublishedAt string` — provider-supplied publication date/age, verbatim
    (ISO-8601 preferred, but stored as the provider gives it; do not fabricate).
- Populate in each adapter from fields it already receives. Where a provider
  gives nothing, leave nil/empty — never invent.
- **Ordering stays deterministic and dumb:** keep the provider's own result order
  by default (providers already rank). The ONLY task-driven reorder allowed:
  when results carry `PublishedAt` AND the task is recency-oriented (`news`,
  `factcheck`), sort by date desc as a stable secondary pass. No cross-provider
  blending, no rerank model. (This is the literal "pass the signal, let the
  agent judge" rule — the agent gets scores+dates and decides.)

### D3 — Task-aware request shaping
- Map task → the provider's **freshness/time-range** request parameter, per
  provider capability:
  - `news` / `factcheck` → a recency window (e.g. last month) where the provider
    supports it.
  - `academic` → scholarly hint where supported.
  - others → unchanged (no param).
- **EXACT provider param names/values are to be confirmed in grounding** (Brave,
  Tavily, Firecrawl each differ — e.g. Brave `freshness`, Tavily
  `time_range`/`topic`, Firecrawl `tbs`). Do not assert them unverified.
- **Safety:** freshness must be a *boost/hint*, not a hard zero-result filter
  where avoidable; if a provider only offers a hard filter and it returns empty,
  the existing fallback chain still tries the next provider. Conservative windows
  (month, not day) to avoid empty results for the "this week" case.

### D4 — Planner taxonomy honesty
- `plannerRules` currently covers 9 of the advertised tasks; `TaskSemantic` and
  `TaskExtract` have no rules (can never be classified). **Add minimal rules for
  them or drop them from the advertised set** (grounding decides which is
  honest — `TaskExtract` is a route-matrix key for the extract path, likely
  should NOT be a search intent; `TaskSemantic` may fold into research).
- Add high-value recency/event phrases the dogfood exposed as missing (e.g.
  `this week`, `tonight`, `near me`, `upcoming`, `events`, `concert`,
  `schedule`, `happening`) to the `news` rule — acknowledging the keyword
  classifier is a **best-effort fallback**; the reliable signal is the agent
  specifying the task (D1). Not whack-a-mole: add a small, defensible set.
- Fix `researchPipeline`: classify the question to drive its fan-out instead of
  the hardcoded `[TaskGeneral, TaskResearch, TaskDocs]` (whose routes overlap so
  it usually hits one provider 2–3× and self-dedups).

## Non-goals (v0.5.0)
- No adaptive/learning router; no persisted routing stats (that is a separate,
  later, agent-facing feature — see roadmap v0.7.0).
- No Nólë-side quality scoring or answer synthesis.
- No cross-provider result blending/dedup beyond what `research` already does.
- No change to the provider matrix ordering itself (only *which task selects
  which row* now actually happens). Matrix reorders still require sanitized
  evidence per existing policy.

## Files in scope (anchors; grounding will produce exact briefs)
- `internal/core/types.go` — `SearchResult.Score`, `.PublishedAt`; response
  `task_source`.
- `internal/core/service.go` — `Search`: auto-classify on empty task; thread
  `task_source`; recency secondary-sort hook.
- `internal/core/planner.go` — taxonomy fix + recency/event phrases.
- `internal/providers/{brave,tavily,firecrawl,ddgs}/*.go` — populate
  score/date; send task-driven freshness param (capability-gated).
- `internal/mcpserver/tools.go` — `task` enum + per-value descriptions +
  auto-detect note; surface `task_source`.
- `internal/cli/{search,research}.go` — research pipeline classify; surface
  `task_source` in human/JSON output.
- `internal/cli/http.go` — inherits auto-classify via `Service.Search`; ensure
  `task_source` flows to REST JSON.
- Tests: planner (concert/this-week → news), service (empty task → classified
  route; explicit task wins; unknown task → lenient), adapters (score/date
  parsed; freshness param sent per task), MCP (enum advertised; task_source
  present), research (classified fan-out).

## Success criteria
- A no-task search for "concerts this week" classifies as `news` (after D4) and
  the response `task_source` reads `detected`; an explicit `--task docs` reads
  `supplied` and routes via the docs matrix.
- `news`/`factcheck` searches send a recency parameter to capable providers, and
  results carry `PublishedAt` where the provider supplies it; recency-oriented
  results are date-sorted.
- Tavily results carry `Score`; the agent receives scores+dates and Nólë applies
  no quality judgment of its own.
- The MCP `search` tool advertises a `task` enum + "auto-detected if omitted".
- Full gate green: `gofmt`, `go vet`, `go test -race ./...`, `./scripts/audit.sh
  --ci`, `./scripts/secret-scan.sh`; seed-fuzz unaffected.
- No breaking JSON changes (all new fields `omitempty`/additive).

## Process
Grounding workflow (code-anchored briefs + adversarial design review) →
feature branch → main-loop sequential implementation with tests (compile-green
throughout) → adversarial review workflow → full gate → CHANGELOG + release-notes
→ PR + Codex review → tag `v0.5.0` → release.yml. Do not install unreleased
v0.5.0-dev over the user's machine binary; only released tags get installed.
