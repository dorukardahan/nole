- **v0.7.0 — trust:** honest quota metadata + drift signal + cost-cap clarity + breaker state in `provider_status` + real `/health` readiness. Freezes the JSON envelope shape.
- **v0.8.0 — observability:** `NOLE_LOG=json` (stderr-only), `nole config` dump, `doctor --json`, OBSERVABILITY.md. Pure reader of v0.7.0's frozen shape.

**Key gate fact (scope review):** v0.7.0 adds NO MCP tool — it only adds *fields* to existing `provider_status`/`budget_status` and changes the `/health` REST body. So `scripts/verify-integration-evidence.sh` + `scripts/check-integration-evidence.sh` tool-list greps stay byte-identical → NOT touched (the crucial difference from v0.6.0, which added two tools).

## Evidence-based deviations from the raw design brief

1. **Item A keeps all `FreeQuota` integers at 1000 and keeps `RefreshMonthly`** (brief proposed Brave→2000, Firecrawl→one-time-500/RefreshNone). Verified June 2026:
   - Brave killed its flat free tier Feb 2026; new accounts get ~1000 queries from a $5/mo credit then *metered billing on the CC*. Over-counting now risks a surprise bill, so 1000 is the fail-safe floor (NOT 2000). `setup_doctor_test.go:272` also asserts `free_remaining=1000`.
   - Firecrawl's own pricing page now says 1000 credits/**month**; only third-party trackers say one-time-500. Flipping to `RefreshNone` on contradicted evidence would be *less* honest and would break Firecrawl out-of-the-box.
   - ⇒ The dishonesty was never the integer (~1000 is right for all three today) — it was presenting bare numbers as authoritative. Item A becomes *metadata + "estimate, verify dashboard" labeling*; the **drift signal** (Item B) carries the honesty. **R1 (Firecrawl ledger migration) is eliminated** — the riskiest part of the brief is gone.

2. **Item C: cost-capped + no cap stays fail-closed + loud, NOT auto-$5** (brief recommended default-$5). North-star is explicit: "fail closed on cost, never surprise with a bill; a false-positive reject is safer than allowing surprise spend." Auto-$5 authorizes unrequested spend. So: keep premium blocked, but surface a loud, clear reason + `HardCapSource`.

## Item B — Drift signal (Decide-said-yes, provider-said-429)

Files: `internal/providers/providerhttp/errors.go` (or new helper), `internal/core/types.go`, `internal/core/quota.go`, `internal/core/service.go`.

- `providerhttp.IsQuotaExhausted(err) bool` — `errors.As` to `*HTTPStatusError` with `StatusCode==429`. (Field already exported.) Deterministic, no string-matching.
- `types.go`: `DriftSignal{Provider, Reason, ObservedAt string}`; `BudgetStatus` += `HasDrift bool` + `DriftSignals []DriftSignal omitempty`; `ProviderStatus` += `DriftWarning string omitempty`.
- `QuotaLedger` interface += `RecordDrift(provider, reason string)`. Only `MemoryQuotaLedger` implements it (verified: no test doubles). RecordDrift: holds `l.mu`, upserts a `map[string]DriftSignal` keyed by provider with `ObservedAt=nowUTC()`, does NOT debit/touch FreeRemaining, persists into `quotaLedgerFile` (new `DriftSignals` field).
- Persistence: `reloadFromDiskLocked` union-merges DriftSignals (keyed by provider, keep newest `ObservedAt`) — mirrors the `SpentCents` max-merge. `BudgetStatus()` stays a PURE read; ages out signals >24h **in output only** (never writes).
- Service wiring — **critical correction**: drift goes in the error-path `continue` branch of `searchUncached` (service.go:191-195) and `extractUncached`, NOT in `recordLocked` (Record is success-path-only and already never debits on 429):
  ```go
  if err != nil {
      lastErr = err
      if providerhttp.IsQuotaExhausted(err) && decision.FreeRemaining > 0 {
          s.ledger.RecordDrift(name, "provider returned 429 while local free_remaining > 0")
      }
      trace = append(trace, attemptWithDecision(name, "failed", "provider_error", decision, latency, 0))
      continue
  }
  ```
- `ProviderStatus()` sets `DriftWarning` per provider from a recent drift signal (read `BudgetStatus().DriftSignals` once, map by provider).
- **Drift flags at `FreeRemaining > 0`, no percentage band** (O3, keep it dumb).
- **Breaker interaction (C2):** after `NOLE_BREAKER_THRESHOLD` (5) consecutive 429s the breaker opens → `ErrCircuitOpen` (not `*HTTPStatusError`) → drift stops. This is intended: drift is a best-effort EARLY signal ("I observed a direct 429"). Documented + tested.
- **One-directional (north-star):** Router must NEVER read drift state. Test asserts router has zero drift references.
- Tests first: `TestIsQuotaExhausted` (table), `TestSearch_429WithRoomRecordsDriftNoDebit`, `TestSearch_429AfterExhaustionNoDrift`, `TestDriftSurvivesReload`, `TestDriftUnionMergeTwoProviders`, `TestDriftAgesOut24h`, `TestProviderStatus_ShowsDriftWarning`, `TestRecordDriftConcurrent` (-race), `TestDriftStopsAfterBreakerOpens` (6×429), `TestRouterIgnoresDrift`.

## Item D — Breaker state in provider_status

Files: `internal/providers/providerhttp/breaker.go`, `internal/core/types.go` (ProviderStatus), `internal/providers/{brave,tavily,firecrawl}/*.go` Status().

## North-star guardrails (one line each)
- A: report what we issued, label it an estimate, refuse to model unverifiable balances.
- B: drift = "my counter disagreed with a 429" — never reorders routes, never debits, ages out.
- C: never authorize spend the user didn't set; block + explain.
- D: expose raw breaker state only — no healing_eta / recommended-fallback / generation.
- E: binary readiness, no scoring/latency/quality, orthogonal to budget; 503 is a fact.
- Cross: stderr/envelope-only, no field carries a key value.
